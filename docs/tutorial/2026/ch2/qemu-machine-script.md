# QEMU 主板建模流程（口播稿）

> 对应文档：`docs/tutorial/2026/ch2/qemu-machine.md`
>
> 适用对象：QEMU 入门者、刚接触系统模拟的同学
>
> 讲解建议时长：20～30 分钟（可按课堂节奏裁剪）

大家好，我们这一节来聊一个看起来“没有 CPU 那么显眼”，但在 QEMU 里非常核心的话题：

**machine model，也就是主板模型。**

如果你已经开始读 QEMU 源码，你大概率会遇到这类困惑：

- 为什么同样是 RISC-V，换个 `-machine`，设备布局完全不一样？
- 为什么明明选了 CPU 型号，系统还是起不来？
- 为什么设备代码写好了，却找不到它到底在什么时候被挂上去？

这些问题背后，很多都不是 CPU 细节问题，而是 machine 层的问题。

所以今天这节课，我们的目标不是“背代码”，而是建立一个稳定的理解框架。你听完之后，至少应该能做到三件事：

1. 从概念上说清 machine 和 CPU、device 的边界；
2. 沿着 `-machine` 参数走到 `mc->init()`，知道整机是怎么搭起来的；
3. 读一个机型（例如 `virt`）时，知道先看哪里、再看哪里。

---

## 一、先建立一个最重要的直觉：machine 是“整机装配层”

我们先讲一句可以反复拿来用的话：

**machine 不是某个零件，而是“把零件装成整机”的那一层。**

你可以把 QEMU 想象成在模拟一台完整计算机：

- CPU 是计算核心；
- 各种 device 是外设；
- bus 是连接关系；
- interrupt controller 负责中断分发；
- firmware / FDT / ACPI 负责启动信息；
- 而 machine 负责把这些内容组织成“可启动、可运行、可扩展”的整机。

所以 machine 一般会关心：

- CPU 拓扑（几个 socket、每个多少 core/hart）；
- 内存地图（RAM/ROM/MMIO 分布）；
- 总线与设备挂载位置；
- 中断路由；
- 启动入口、设备树或 ACPI 表。

请注意：

- CPU 模型描述“这颗 CPU 是谁”；
- machine 模型描述“这台机器长什么样”。

这两个维度是正交的。

---

## 二、从命令行理解：`-machine` 与 `-cpu` 的分工

我们先从使用视角来看，便于建立直观感受。

当你写：

- `-machine virt`
- `-cpu rv64`

其实你在做两次选择：

1. 选择主板模板（整机骨架）；
2. 选择处理器实现（CPU 细节）。

如果给初学者做类比，可以这样说：

- `-machine` 像在选“主板+芯片组+默认设备布局方案”；
- `-cpu` 像在选“插到这个方案里的处理器型号”。

因此，很多“跑不起来”的问题并不是 CPU 本身不对，而是 machine 与设备布局、固件路径、内存地图等不匹配。

这也是为什么我们学习 machine，不是锦上添花，而是排障必需。

---

## 三、QOM 视角：machine 在类型系统里长什么样

QEMU 的对象系统叫 QOM。machine 也是 QOM 类型，不是“例外机制”。

典型模式是：

1. 定义并注册 `TypeInfo`，让该机型成为 `TYPE_MACHINE` 的子类；
2. 在 `MachineClass` 的 `class_init` 里设置关键字段；
3. 在 `instance_init` 或后续初始化阶段准备实例状态；
4. 最终在 `mc->init` 中执行板级装配。

你在机型代码里会经常看到这些配置位：

- `mc->desc`：机型描述；
- `mc->init`：板级初始化入口；
- `mc->max_cpus`：机型允许的最大 CPU 数；
- `mc->default_cpu_type`：默认 CPU 类型；
- `mc->default_ram_id`：默认 RAM 对象标识。

其中最关键的是：

**`mc->init` 是“把一台机器拼起来”的总入口。**

你只要记住这条，就知道读机型时先抓什么。

## 四、运行时主流程：`-machine` 怎么走到 `mc->init()`

我们把运行时路径压缩成一个“3+1”流程：

### 第 1 步：解析并选择机型

QEMU 启动后解析参数，处理 `-machine`。如果你显式指定，就按名称匹配；没指定就选择默认机型。

这一步产出的是一个 `MachineClass`。

### 第 2 步：实例化 machine 对象

随后 QEMU 按选中的类去创建 `MachineState` 实例，并将对象挂入全局对象树。

到这里可以理解为：

- 类（class）已经选好；
- 实例（instance）已经创建；
- 但整机还没“通电”。

### 第 3 步：调用板级初始化

QEMU 进入 `machine_run_board_init()` 后，核心动作是调用 `machine_class->init(machine)`。

这就是“总装阶段”真正开始的时刻。

### +1：初始化完成后进入后续阶段

当板级初始化结束，才进入更后面的启动阶段、设备运行阶段。

所以若系统在早期启动异常，排查顺序通常是：

- 先看机型是否选对；
- 再看 `init` 是否按预期创建对象并连线；
- 最后再看单个设备内部逻辑。

## 五、以 RISC-V `virt` 为例：把抽象概念落到实际动作

这一段建议你讲慢一点，给同学建立“读代码地图”。

在 `virt_machine_init()` 这类函数中，我们通常会看到：

1. 按 socket/cluster 维度创建 CPU 相关对象；
2. 设置 `cpu-type`、`hartid-base`、`num-harts` 等属性；
3. realize 到系统总线；
4. 分配/映射 RAM、ROM 与 MMIO 区域；
5. 初始化中断相关模块（如 PLIC/ACLINT/IMSIC）；
6. 挂载常见设备（串口、RTC、PCIe、virtio-mmio 等）；
7. 组织启动信息（设备树或 ACPI）。

你会发现机型 init 的叙事方式通常是：

- 先“搭骨架”（CPU/内存/总线）；
- 再“接神经”（中断）；
- 再“装器官”（外设）；
- 最后“准备开机信息”（FDT/ACPI/firmware）。

这就是一个很稳的阅读顺序。

## 六、课堂可直接用的“命令行演示段”

如果你要现场演示，推荐这几个简单命令作为辅助（不需要展开过深）：

1. 查看机型列表：

```bash
qemu-system-riscv64 -machine help
```

2. 观察某机型能否最小化启动（根据你的环境替换内核/固件参数）：

```bash
qemu-system-riscv64 -machine virt -nographic
```

3. 在 monitor 里观察对象树（重点看 machine 下挂了哪些对象）：

```text
info qom-tree
```

你在口播里可以强调：

“我们先不改代码，先观察对象树。对象树看懂了，再回源码会快很多。”

## 七、初学者高频误区（建议课堂重点提醒）

### 误区 1：把 machine 和 device 混为一谈

很多同学看到设备初始化代码，就以为那就是 machine。实际上：

- device 关心“设备内部行为”；
- machine 关心“设备放在哪里、怎么连起来”。

### 误区 2：只盯 CPU，不看内存地图

启动失败经常和地址空间冲突、映射错误有关。只看 CPU 往往排不出来。

### 误区 3：读代码不分层，直接从头硬啃

建议固定顺序：

1. 先看 `MachineClass` 配置；
2. 再看 `mc->init` 主流程；
3. 再追具体设备初始化。

### 误区 4：不知道“默认值”从哪来

很多参数来自 `MachineClass` 默认配置，不在命令行显式写出。读类初始化时要特别留意。

## 九、互动提问（课堂现场可直接用）

你可以在讲到一半时抛 3 个问题，让同学快速自检：

1. 如果只改 `-cpu` 不改 `-machine`，整机内存地图会不会自动变化？为什么？
2. 如果某个外设没有出现在对象树里，你第一反应应该去看设备源码，还是机型 `init`？
3. `mc->init` 这个入口为什么对排查“起不来机”特别关键？

这类问题能帮助同学从“记概念”转向“会排查”。

## 十、一句话串讲版（时间不够时可直接念）

如果你的时间只剩 2 分钟，可以用这段压缩版：

“QEMU 的 machine 模型是整机装配层。它在 QOM 中作为 `TYPE_MACHINE` 子类注册，通过 `MachineClass` 提供默认配置和 `mc->init` 入口。运行时，QEMU 先根据 `-machine` 选机型，再创建 `MachineState`，最后在 `machine_run_board_init()` 中调用 `mc->init()` 完成 CPU、内存、总线、中断和基础外设的组装。读机型代码时，先抓 `init` 主流程，再追设备细节。”

## 十一、收束总结（结尾可直接口播）

好，我们最后收一下这节课最核心的三句话。

第一句：

**`-machine` 决定整机骨架，`-cpu` 决定处理器细节。**

第二句：

**machine 是 QOM 类型，不是特殊通道；机型核心入口在 `mc->init`。**

第三句：

**读机型别乱冲：先机型选择，再对象创建，再看 `init` 装配。**

你把这三句话真正吃透，后面读 QEMU 的外设建模、总线机制、中断系统，都会顺很多。
